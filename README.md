# AI Daily Intelligence — V1 正式完整版

**繁體中文 · 免費 RSS 與開源本地模型 · 每日香港時間 07:40 預定開始生成 · 08:00 目標可閱讀 · 英文長篇至少 1,000 字**

本專案的第一個完整正式版本為 **V1**（2026-10-09），包括經驗收的英文閱讀、離線查字與每日自動出稿。早期開發階段的版本編號只代表內部試作紀錄，不是獨立的正式發布版本。專案著重**內容價值、準確性、計算及閱讀效率**。不需要 OpenAI API。網站現可選擇使用 Supabase 電郵登入；只有登入後及主動匯入的生字、詞義和複習紀錄會傳送至雲端。閱讀位置、已讀紀錄、理解題答案仍保存在各裝置本機。

> **狀態：已透過 GitHub Pages 部署。** 最新文章依據有來源連結的 RSS 資訊編寫，未經獨立全面事實核查；部分段落屬教育性的比較與推論，非記者原始報道。
>
> 本程式無法保證任何新聞或生成內容 100% 正確。「HKDSE 5★」是學習目標，不是模型已獲認證的英文難度。程式結構檢查不能取代專業事實核查。


正式上線及核對設定：[V1 GitHub 驗收清單](docs/FINALISE_WEBSITE_V1.md)。**注意：**生字、答案、學習進度與備份格式的內部 schema 號碼不是網站發布版本，不應更改，否則舊使用者資料可能無法還原。

## 本機預覽

要求 Python 3.11+，可先**不用安裝模型**而試用虛構練習文章：

```bash
python scripts/preview.py
```

根據終端機顯示的 `http://localhost:...` 網址開啟。這只是本機網站，不是實時更新。

## 零付費部署至 GitHub

1. 在 GitHub 建立 **Public** Repository，並把 ZIP 解壓後的**內部檔案**上傳到根目錄，包含 `.github/workflows/daily.yml`。
2. 在 Repository 的 **Settings → Pages → Build and deployment → Source** 選擇 **GitHub Actions**。
3. 確認 GitHub Actions 有 `contents: write` 所需權限，以保存每日報告。
4. 前往 **Actions → AI Daily Intelligence — free daily briefing → Run workflow**，手動執行一次並查看完整日誌。
5. 檢查模型安裝、RSS 預抓取、模型生成、網站發布及 Diagnostics。成功後，從 **Settings → Pages** 取得實際網址。

**重要限制：** GitHub 排程可指定 `Asia/Hong_Kong`，但預定 07:40 觸發不保證準時，08:00 可閱讀是目標而非保證；RSS 可能失敗，免費公開 Repository 的排程長期無活動時可能停用。下載 Ollama 與模型也可能在免費 Runner 超時或資源不足。只有在真實部署後才可確認實際成功率。公開網站上的日報任何人都能讀取，請勿將個人備份或秘密金鑰上傳到 Repository。

## 模型與翻譯的速度選擇

- **預設 `TRANSLATE_ENABLED=0`：** 不呼叫第二次本地模型生成中文全文，保留文章內一鍵生字翻譯（離線預載詞典）。
- 如果願意增加本地模型執行時間，將 workflow 的 `TRANSLATE_ENABLED` 改成 `'1'`，可以**嘗試**生成全文繁體中文翻譯；翻譯不一定能通過格式檢查，也不保證語義完全準確。
- 模型透過 `OLLAMA_MODEL` 指定，預設 `phi3:mini`。模型更換前應先量度 CPU／RAM、英文品質及失敗率；沒有任何模型被保證最好。
- 免費詞典可能缺詞、詞性錯誤或不符合當前語境；不要把點擊查字結果視作已核證的學術翻譯。

## 每日公開發布與準時性驗證（2026-10）

- **07:40 香港時間**：`daily.yml` 預定觸發 RSS 新聞收集及免費本地模型報告生成，預留約 20 分鐘，目標在 **08:00 前可閱讀**。GitHub Actions 可能延遲或略過排程，不能保證整點交付。
- **08:05 與 09:17 香港時間**：`audit.yml` 分別進行早段和覆核兩次獨立檢查，從公開 GitHub Pages 核對當日文章及來源，並核對是否有當日 `schedule` 觸發且成功的生成流程。08:05 的驗證成功僅證明驗證執行時文章可讀，不能精確證明 08:00 已上線；GitHub 可能延遲觸發檢查。
- 驗證結果分開顯示 **最新文章可用性** 與 **品質警告**（來源摘要、少於 1,000 字）；流程成功不等於新聞獲完整事實核查。
- 日期過期、缺乏來源、示範文章被當作正式新聞、或沒有成功的定時生成流程，驗證會顯示紅色失敗，而不是冒稱每日有新報告。
- [查看每日獨立驗證](https://github.com/Tom-gpt65/ai-daily-intelligence/actions/workflows/audit.yml)；[查看每日生成紀錄](https://github.com/Tom-gpt65/ai-daily-intelligence/actions/workflows/daily.yml)。
- 當 RSS 沒有足夠可用新聞時，保留舊報告並明確標示，不製造新日期、無來源消息或假新聞。
- 英文報告編寫目標改為 **至少 1,000 字，通常約 1,100–1,350 字**；免費模型被拒絕時加入明確標示的批判閱讀練習，不把練習題當成已核實新聞。
- 程式更新造成的 `push` 工作只測試與發布網站，不再每次重新下載大型開源模型；定時及手動工作仍會生成新文章。

## 自動生成失敗時的保護（2026-10-09 更新）

- **07:40（香港時間）**：嘗試生成一篇當日 AI 新聞文章；**08:00 是目標可閱讀時間，不是保證**。
- **08:05、09:17**：獨立核實公開網站是否已顯示當日有來源的文章，以及定時生成是否真正成功。會分開顯示「網站資料是否正確」、「文章是否在 07:40 後更新」及「排程有否成功」；文章時間不能證明網站恰好 08:00 已可開啟。
- **08:20、09:40**：如文章仍未在早上更新，補救工作流程會檢查是否已存在正在執行的定時／手動新聞生成；如無，最多補救兩次。單純的程式碼部署不會阻止新聞補救。
- 新聞提交若遇上別人同時更新 GitHub，程式會重新讀取最新 `main`、合併歷史索引、比較帶時區的發布時間並安全重試；不會強制覆蓋分支。
- 沒有新 RSS 消息時，寧願保留舊文章並清楚顯示，而不會以舊新聞冒充新消息。
- 修復後的 Github Actions **程式測試通過，不代表隔天定時生成已被證實可靠**。真實成功率須按日記錄。

## 長篇英文閱讀標準（2026-10-09）

- **不可低於 1,000 個英文單字**；目標約 **1,100–1,350 字**，結構檢查容許上限約 1,550 字。報告的詞數由實際英文正文計算，不包含網站導覽文字或題目。
- 閱讀時間按你選擇的每分鐘 90／115／145 字估算；1,000 字通常需要約 7–12 分鐘，而完成理解題及訂正需更多時間，不能再宣稱每天只需五分鐘。
- 免費開源模型如生成太短、引用無根據、表述重複或含違規指令，系統會拒絕改寫並嘗試有來源編號的原創分析教材。**若新聞來源少於三則或仍不足 1,000 字，應維持上一版並明確標示，不得把短文冒充合格長篇。**
- 原創教育文章按不同新聞類別討論證據、條件推論、反方觀點、跨文本比較與語篇目的；但只讀取 RSS 摘要不能保證完整新聞深度，亦不能把整篇稱作 HKEAA 官方 Level 5★ 標準。
- 詳見 [HKEAA 英文評核大綱](https://www.hkeaa.edu.hk/DocLibrary/HKDSE/Subject_Information/eng_lang/2026hkdse-e-elang.pdf)。Paper 1 Reading B2 為較困難部分；本網站內容屬自主練習而非官方真題或認證分級。

## 內部試作紀錄：高階閱讀與操作修正

- **與考評局資料對照：** HKEAA [2026 Assessment Framework](https://www.hkeaa.edu.hk/DocLibrary/HKDSE/Subject_Information/eng_lang/2026hkdse-e-elang.pdf) 明列主旨、詞義、語氣、論證、語言技巧及跨來源整合等閱讀技能。其 2026 英文資訊日 [官方簡報](https://www.hkeaa.edu.hk/DocLibrary/Event/archive/2026/2026_HKDSE_Info_Day_English_Seminar_Website.pdf) 亦列有 T/F/NG、matching、pronoun reference 等形式。本網站的七題為原創學習練習，**未覆蓋全部正式試卷題型，亦不能聲稱相當於 5★ 官方難度**。
- **防止文字灌水：** 為長文加入跨段四詞片語相似度診斷。接近複製貼上的段落、漏引來源及低於 1,000 字的新稿會被拒絕；模型稿未達標可降級為已明確標示的來源式教材。
- **證據優先：** 至少三則新聞、至少兩段實質 RSS 描述，合計標題及摘要至少 85 個英文單字，才考慮生成千字長篇。只是標題的 RSS 不會誘發模型下載或當日新稿發布；條件不足時保留舊稿。這是啟發式門檻，不是事實核查。
- **更具體的內容：** 當沒有安全的來源特定改寫模板時，備援文章可加入最多 18 字、明確歸屬原始 RSS 的短摘錄。這些內容並非獨立證實的事實，背景推論須明確區分。
- **DSE 練習改善：** 比較題加入每日真實的來源標題；語境詞義題從當日出現的詞語輪換，減少每日相同問題及固定答案的情況。書面題仍只提供透明評分指引，沒有假稱可以無誤自動評卷。
- **iPhone 長文導航：** 文章新增段落編號，並可直接由來源快捷選單跳到引用所在段落；保留查字、逐段翻譯、全文翻譯中斷接續及閱讀進度紀錄。
- **持續驗證：** `longform-validation.yml` 在不佔用 Pages 發布鎖的情況下測試內容與 1,000 字要求；另有 Chromium／WebKit 真實瀏覽器模擬。每次測試通過**不等於**現實新聞獲全面核實，亦不保證未來每天 08:00 準時上線。

## 內部試作紀錄：每日出稿可靠性審查（2026-10-09）

- 保留 07:40 香港時間每日主要生成流程和 08:00 目標，不聲稱 GitHub 排程能百分之百準時執行。
- 08:20、09:40、10:25、12:25 檢查是否缺稿。只有公開網站當日文章沒有通過日期、至少 1,000 字正文、至少三則來源、七道理解題，以及索引一致性檢查時，才考慮啟動補救；仍然每日最多額外觸發兩次。
- 08:05、09:17、13:17 分別進行獨立核對。原定排程失敗和補救成功分開記錄；補救成功不能冒稱原定 07:40 排程成功。
- 報告索引加入 `updated_at`。同日文章即使標題、字數及來源數目不變，網站也可檢測新版本。
- 公開網站已加入 CSS、JavaScript、PWA 快取及長篇文章要求的驗收；未更改生字、閱讀進度或測驗的本機儲存鍵。
- 不使用沒有來源的當日假新聞填補缺稿；來源不足時明確保留舊報告。網絡、免費模型、GitHub 排程、Pages 部署及外部翻譯服務仍可能故障，無法保證每天準時提供全新且已獨立核實的新聞。

## 內部試作紀錄：每日閱讀材料及逐詞離線字典（2026-10-09）

以下策略取代上文較早的「沒有新 RSS 就只能保留舊文章」做法。

- 香港時間 **07:05**，獨立 `early-reading.yml` 預定建立當日備援教育文章；不用 RSS、商業 API 或本地模型。若已存在合格當日文章則保留，若沒有則使用原創 AI 素養教材庫，每篇至少 **1,000 個英文單字**及 **7 道閱讀理解題**。
- 香港時間 **07:40**，`daily.yml` 嘗試取得當日 AI 新聞；只有來源及文章品質合格，而且**所有可點擊英文詞形都有真實的離線繁體中文詞義**，才可發布當日新聞版。否則保留／發布清楚標示 **「AI 延伸閱讀 · 非即時新聞」**的備援版。
- 詞義由既有詞典、人工整理的補充字庫和必要時的免費本地模型補齊；程式使用 `edition_guarantee.complete` 作逐字硬性驗收，不以「待查」「未知」或只顯示英文原詞冒充中文翻譯。模型的翻譯亦可能存在語義錯誤，未經人工逐項核證。
- 單日原本有合格新聞時，稍後完成的備援工作**不可覆蓋較高資訊價值的新聞文章**。
- `recover_daily.py` 與 `audit_publication.py` 也驗證離線詞義覆蓋率；延伸閱讀與即時新聞的來源要求不同，兩者均需通過篇幅、日期與題目檢查。
- GitHub Actions 的定時任務可能延遲、略過或因平台故障無法執行；**不存在可以在沒有其他基礎設施的情況下保證每日 08:00 準時上線的絕對承諾**。備援與多次審核旨在降低缺稿風險，並準確披露未達成的狀況。
- 保留原本的詞彙、生字、答案及閱讀進度 `localStorage` 儲存鍵，不會因新版本重設使用者資料。

詳細啟用步驟與 Row Level Security：[`docs/CLOUD_SYNC_SETUP.md`](docs/CLOUD_SYNC_SETUP.md)，建表 SQL：[`docs/SUPABASE_VOCABULARY.sql`](docs/SUPABASE_VOCABULARY.sql)。

同步範圍只包含**生字、詞義、複習等級及下次複習日期**；閱讀位置和測驗答案仍只保存在各裝置。本機既有生字必須由使用者主動選擇加入雲端，原有 JSON 備份功能和 V1 正式版本名稱保留。

## V1：首個完整正式版本（2026-10-09）

**正式版本由 V1 開始計算。** 這是獲使用者同意的大型功能版本發佈；往後逐日出稿、歷史補檔、測試及一般錯誤修正**不會自動升級 V1 版本號**。

- **內容與事實一致性：** 修正開源軟件安全新聞錯配生物研究分析，以及機器人新聞使用不相關泛論的問題；新增標題優先的主題分類、RSS 系統文字與提示詞污染過濾、來源配對回歸測試。
- **每日教材多樣性：** 教材庫從 12 個擴充至 24 個原創主題，連續兩天不重用相同主題段落。全庫 818 種可點擊詞形均具離線繁體中文詞義。
- **字體與版面：** `site/v1.css` 使用無外部字型下載的繁體中文介面與英文閱讀字體，改善窄屏行寬、行距、最小操作面積、焦點提示和減少動畫。
- **減少雜訊：** 精簡非必要的宣傳式文字，保留但摺疊翻譯私隱與資料來源警告。
- **歷史閱讀：** 背景日報核對不會打斷已選擇的過往文章／生字複習。
- **學習資料：** 原有生字庫、閱讀進度、選擇題、書面答案與匯出／匯入的本機儲存鍵完全沿用。
