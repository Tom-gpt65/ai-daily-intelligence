## 修正與限制

- 保存最多三十個去重事件，依歷史來源身分、已使用分析、資料量及來源多樣性選材。允許尋找不同事件組合，禁止以換日期、同義詞或填充重試同一文章。
- 舊 `source_outline_v2` 與 9／10 日修正版保留。只有新的來源條件分析需要本地免費模型；模型按來源順序生成問題、競爭解釋及假設比較方法，不生成新聞事實。來源歸屬與短引文由程式組裝。
- `source_analysis_v3` 每句須有假設語氣；禁止新增數字、日期、網址、未提供名稱、報道式宣稱、抄錄摘要及遺漏／錯置來源。保存結構後，讀取與發布端重新組裝及核驗，不能依賴已儲存的 pass 標記。
- 第二次真實 runner 試驗產生了連串問句及超長段落，兩份草稿均拒絕。改用固定句數的段落陣列；三至五個來源各有論證與比較方法，介紹與結論各三句。第三次實跑揭露精確解碼字數限制會讓模型黏連單詞，改為給解碼足夠拼字空間，再核驗陳述句 20–45 詞及完整文章 **1000–1550 詞**，提示目標為每句 27–32 詞。沒有裁切、填充或放寬原創性門檻。過往新聞正文不再放入模型來源提示，避免把上一日題材混入新來源；完整歷史比較仍保留。
- 名稱只能出現在程式的來源標題／短引文，模型分析不准自行組合品牌、產品或人物關係；僅有假設語氣不足以防止錯配關係。介紹須涵蓋至少三個來源、結論至少兩個，並重新核對實際主題詞；不能只寫第一則題材而忽略其餘。
- 第四次真實 runner 仍拒絕兩份草稿：名稱偵測誤把摘要句首的 Artists／At 視為名稱，同時模型仍寫入 Microsoft、重用摘要及使用報道式句子。修正名稱偵測的句首判斷；模型輸入匿名化，解碼只容許普通句首和小寫內文（AI 除外），不使用大型有界詞數文法。20–45 詞及完整文章門檻仍由發布端核驗。改良提示要求可比較的共同觀察指標，禁止猜測真實公司的動機、行為及使用重複段落模板。
- 未完成／非 JSON 的模型回應另記錄精確原因及原始公開分析文字，不再一律誤報模型不可用；仍只容許一次完整重新生成。
- 第五次實跑仍因抄錄摘要／報道式用語拒稿，名稱及單詞黏連問題未再出現。模型現在只接收去除名稱的主題詞，不接收來源正文或過往新聞；來源事實保持於程式引用段落。假設實驗須有共同可觀察結果，不能把「控制變量相同」本身說成實驗限制。
- 原來的五詞、近 60 天、未四捨五入 **嚴格 <16%**、正文 24 詞跨日重用、文章內 16 詞／完整句重複、1000–1550 詞、完整離線詞義及七題檢查全部保留；原始 9／10 日文章仍在比較語料內。
- 最多一次針對真實拒稿原因重新生成；不拼接或補字數。模型下載／執行／品質／詞典失敗時保留清楚標示的舊閱讀。有限教育庫也會耗盡；不將相同練習改日期冒充當日新作。
- 午夜重試不再耗掉 07:40 後的兩次補救限額。每次正式嘗試上傳公開來源及逐則拒稿理由供十四日內調查，不涉及使用者資料。
- 並行發布取回新遠端文章後，不論是否保留較新的嘗試紀錄，都重新核對真正採用的文章日期、類型與備援標示，避免狀態仍指向舊文章。實際本機 Git 測試重現了此問題。
- S1 標籤不變，資產與 PWA 更新至 s1-4；不更改 localStorage 私人生字、備份格式、Supabase 身分或雲端資料。
- 模型的 JSON 解碼順序與閱讀順序一致：引言、各來源論證與比較、結論，避免先寫結論才展開正文。WebKit 原生章節選單的焦點恢復競態已於本機重現；選擇章節時先移交焦點，再執行仍屬同一文章的校正跳轉，並核對跳轉位置維持穩定。

文法、原創性及程式核驗不能證明模型分析的語義或每則來源絕對正確。來源仍未獲獨立事實核查；需要持續抽查。模型在 GitHub runner 執行，不使用付費 API，但須下載約 2.5GB，受網路、Actions 執行時間及配額影響。
