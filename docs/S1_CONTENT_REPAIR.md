# S1 文章生成修正：2026-10-09／10

使用者指出兩篇文章重述論點、重複段落及銜接混亂。本次授權以程式重製 9／10 日；8 日文章、私人詞庫、localStorage 鍵、Supabase 設定與身分契約保留。

## 根因與修正

舊生成器用通用段落湊足字數，依日期選擇銜接語，並反覆比較同一對來源。五詞重疊使用集合，不能量度同一段內容重複出現幾次；段落 Jaccard 門檻 0.68 又會被不同標題、來源及引文稀釋。舊 9／10 日跨日得分 13.18%，因此通過舊檢查，但 9 日仍有 3 個重複長句，10 日有 6 個重複長句及 79 個重複 16 詞片段。之前的綠色測試未證明文章組織及篇內品質合格。

`source_outline.py` 現在依來源主題建立固定論證順序：主旨、每項來源、一次比較及結論。同一分析規則一篇只能使用一次。取消日期輪換、48 次模板重試及補字數素材庫。報道內容限於附來源的標題和每來源最多 18 詞引文；教學分析描述可檢查的問題與條件，不宣稱做過實驗或獨立核實。

任何重複的完整句子（至少 10 詞）、16 詞片段、提前結論銜接或來源結構不符，均拒絕發布。跨日繼續使用五詞、近 60 天、未四捨五入且嚴格 `<0.16` 的門檻，另拒絕正文／結論重用的 24 詞分析片段。只有第一段標準範圍說明不計入此額外長片段規則；它仍計入五詞總重疊。替换前的文章也留在近 60 天比較庫。已發過的來源不能靠修改時間及查詢參數重新當成新報道，即使超過 60 天。

## 自動重製與資料保留

執行 `python scripts/repair_content_history.py --apply`。程式先在暫存副本生成兩篇，檢查來源一致、離線詞義、至少 7 題、問題引文、所有歷史重複率及站點契約，再複製到工作目錄供 Git 原子提交發布。失敗時不替換任何正式文章。

原始 JSON 位於 `site/reports/archive-revisions/s1-original/`，SHA256 仍是原 S1 的兩個值，亦可從不變的 Git 標籤 S1 取得。`S1_PRESERVED_FILES.json` 將保護目標移到這兩個備份；8 日、雲端設定、manifest 及 SQL 仍逐位元保護。重製使用原日期已存的 RSS，不重新冒充當日抓取；`updated_at`／`history_rebuilt_at` 是實際重製時間，`historical_source_reference_at` 只是明示的歷史驗證參考。驗收必須核對原檔 hash、來源完全相同及來源日期窗口，不能藉歷史旗標豁免來源驗證。

重製結果：9 日 1,225 詞、8 段；10 日 1,219 詞、8 段；兩篇五詞重疊 **9.254709254709255%**，重複長句／16 詞片段均為 0，正文／結論共用 24 詞片段為 0。各有 5 個原日期來源、7 題及完整離線詞義。原文與重製文也逐一比較，均 `<16%`。可機讀證據在 `S1_CONTENT_REPAIR_EVIDENCE.json`。

`rebuild_v3_history.py`／歷史 workflow 只產生暫存預覽，保留 8 日，不具正式發布權限。前端保持 S1；資源版本為 `s1-3`，快取為 `ai-daily-S1-3-reading`。測試包括 V1／V2／V3／S1-2 升級，保留裝置、帳戶、待同步事件及登入身分。

機械檢查不能證明所有語意、來源真實性或教學品質。來源主題規則是有限的；未支援、同主題重複、資訊不足、詞義缺漏或新內容重用分析素材時，新聞生成會被拒絕。可提供已標示的教育／舊日期閱讀，並顯示失敗原因；不能保證每日都有真實新聞，亦不宣稱零故障。
