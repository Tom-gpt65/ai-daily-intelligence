## 驗收方法

`python -m unittest discover -s tests -v` 執行全部 Python 回歸。V2 包括翌日完整編稿、缺詞拒絕、薄弱 RSS 拒稿、過期／未來來源拒絕、香港午夜預抓取失效、CDN 修訂拒絕、備援先公開再回報新聞失敗、實際引文驗證及跨年 Canary。

`python scripts/morning_canary.py --first-day 2026-10-11` 對 2026-10-11、10-12、10-13、10-18、11-10 測試：07:05 備援 → RSS 中斷 → 真正 `build_live()` 產生有來源的 1,218 字摘要 → 較晚備援不得降級。所有 RSS 輸入均明確為合成測試資料，只存在臨時目錄，從不作為真新聞發布。跨年測試另涵蓋 2026-12-31 與 2027-01-01。

真正 Git 整合驗收使用本機 bare remote，模擬同時更新 main／昨日報告、備援發布、新聞升級及晚到備援。Windows 受限制執行環境可能禁止 MSYS 程序物件；只有遇到該特定限制時跳過此項，本次合併必須以 Linux GitHub Actions 的完整執行結果為準。

Node 驗收包括既有雲端衝突、登入／密碼不落盤、主題對比及實際 Service Worker：V1 公開快取遷移、42 日期限制、100 次 query 刷新只佔一份、保護索引、503 備援及私人端點繞過。

Chromium／WebKit 執行全部既有行動閱讀、排程、版面、主題、Magic Link、密碼登入、兩裝置模擬及離線備份回歸。新增測試先註冊儲存的真正 V1 worker，再於正式網站同樣的子路徑更新 V2，核對公開舊文章、每個帳戶快取、待同步佇列、session、已儲存詞、答案與進度完整保留。

## 保留與剩餘風險

- 過往 2026-10-09 部分題目引文與後來修訂的段落不完全一致。按要求保留歷史原檔；從 V2 新稿起採 `validation_profile: v2` 執行精確引文核對。不得宣稱所有歷史題目均經人工重新驗證。
- 結構檢查、來源連結及中文詞義覆蓋不能證明每項新聞事實或翻譯語境完全正確。RSS 摘要及原創分析清楚分開，並無聲稱獨立全面事實核查或 HKEAA 認證。
- WebKit 模擬及真實 CacheStorage 測試涵蓋升級／已開頁面離線操作；實機 iPhone／iPad 安裝後完全關閉再離線冷啟動仍需實機驗收。不要刪除 PWA 或清空資料作為更新方法。
- 公開 Supabase Auth 健康及匿名讀取拒絕可實測；兩個實際已登入帳戶之間的服務端 RLS 隔離及真實跨裝置同步，沒有使用使用者密碼執行。本次採既有私隱回歸、匿名公開檢查及程式／SQL 零修改確認，不冒稱完成真帳戶測試。

## 維護與回復

日常毋須手動增刪帳戶、清除儲存或改寫報告。失敗時先查最新工作與 `system-status.json`：分辨 RSS、證據不足、缺詞、內容品質、真正 build 失敗與 Pages 未更新。缺詞只加入有實際繁體中文意思、可核實的詞義；不要降低未知詞拒稿規則。

需要回復程式時以 Git PR 回復程式變更，保留報告、Supabase 設定及本機資料。新的公開殼修訂需同步版本 metadata、HTML 資源 query、worker namespace 及所有公開驗證，再執行全部回歸。歷史檔名中的 v1／v7 是相容資源或內部測試名稱，並非要求遷移使用者資料。
